## Summary

영향받는 KNFSD 기능, 확인한 오류, 보안상 의미를 사실과 가설로 구분해 적는다. 제목은 별도 `title` 값에 `기능 + 원인 + 결과` 형식으로 제출한다.

## Root cause

대상 커널 커밋, 저장소 상대 경로, 함수와 줄 번호를 적는다. 아래에는 **해당 커밋의 실제 소스**에서 필요한 부분만 그대로 인용하고, 공격자 입력부터 결함까지의 흐름을 설명한다.

```c
/* 제출 전에 대상 커밋의 실제 소스 조각으로 교체한다. */
```

## Reproduction environment

서버 VM·클라이언트 VM의 커널 커밋, NFS 버전, 활성화한 옵션, 인증·권한, 필요한 마운트 조건을 적는다. `reproduction.md` 또는 `reproduce.sh`에 C PoC 빌드·실행 명령과 실제 관찰을 적어 함께 첨부한다.

## PoC

별도 첨부한 `poc.c`의 입력 구성과 호출 순서, 각 단계의 목적, 기대 관찰 결과를 설명한다. 이 절에 코드 전체를 중복해서 붙이지 않는다.

## Impact analysis

`kasan_read`, `kasan_write`, `controlled_read`, `controlled_write`, `lpe`, `rce`, `info_leak` 중 실제 관찰한 항목과 각각의 로그·실험 근거를 적는다. 한 취약점에서 여러 영향이 입증되면 모두 적고, 미확인·추정 항목은 별도 문장으로 구분한다. KASAN 또는 KCSAN 원본 `.log`를 한 개 이상 첨부하되 로그를 만들거나 다른 실행의 것을 재사용하지 않는다.
